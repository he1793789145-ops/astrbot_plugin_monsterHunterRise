# 怪物猎人素材查询（AstrBot 插件）

在群聊里查询《怪物猎人 崛起：曙光》的素材获取方式、怪物弱点与分部位肉质、
任务奖励，以及「这份素材能做什么武器 / 装饰珠」、武器详情与装饰珠配方，
以图片卡片回复。

面向 OneBot v11（aiocqhttp）平台，已在 AstrBot 4.x 上开发。

**当前版本：1.4.1**（改动见文末「版本更新记录」）

## 指令

| 指令 | 说明 |
|---|---|
| `/mh 素材 <素材名>` | 查素材：哪只怪物、哪个部位/方式、概率、数量，能做什么武器/装饰珠，以及哪些任务可刷 |
| `/mh 怪物 <怪物名>` | 查某只怪物：**弱点**、出现地图、掉落表（一个素材一个方块） |
| `/mh 肉质 <怪物名>` | 查**分部位肉质**：每个部位的斩/打/弹、火/水/雷/冰/龙、晕，含状态变化 |
| `/mh 任务 <任务名>` | 查任务的星级、地图、出场怪物与结算奖励 |
| `/mh 武器 <素材名 / 武器名 / 怪物+类型> [武器类型]` | **双向+系列**：见下表 |
| `/mh 技能 <技能名 / 装饰珠名 / 素材名>` | **三向**：技能→**效果（总述 + 逐等级）**与可用装饰珠配方；珠名→该珠配方；素材名→能做的珠 |
| `/mh 装饰品 <珠名>` | 单颗装饰珠的孔位、技能与所需素材 |
| `/mh help [指令]` | 指令一览；加指令名看示例 |

不带参数、或子命令拼错时会自动回帮助。

**`/mh 武器` 的三种用法**：

| 输入 | 结果 |
|---|---|
| `/mh 武器 怪异化的皮` | 该素材能做的武器，按稀有度降序**只列 4 件**（+「另有 N 件」） |
| `/mh 武器 怪异化的皮 太刀` | 该素材能做的**太刀全部**，两列排版 |
| `/mh 武器 炎火杰大剑` | **武器详情**：攻击/会心/属性/防御、锋利度条、孔位等级（含百龙孔）、武器类型专属信息（盾斧·斩击斧的瓶、铳枪的炮击）、派生（来源 + 可强化为）、所需素材 |
| `/mh 武器 伞鸟枪` | **怪物系列 + 武器类型**：列出「伞鸟衍生」这条武器树里的**长枪**（同理 `雷神龙盾斧`、`镰鼬龙太刀`） |

武器类型可以写：大剑 / 太刀 / 片手剑 / 双剑 / 大锤 / 狩猎笛 / 长枪 / 铳枪 /
斩击斧 / 盾斧 / 操虫棍 / 弓 / 轻弩 / 重弩；系列查询里也可用简称（枪 / 铳 / 斧 /
剑 / 锤 / 笛 / 棍 / 弩）。

**`/mh 肉质` 的几个约定**：

- 列序与游戏内猎人笔记一致：**斩 打 弹 ｜ 火 水 雷 冰 龙 ｜ 晕**（雷在冰之前）
- 物理肉质 **≥45 用橙色标出**——这是「弱点特效」能触发的阈值
- `0` 表示完全无效，压暗显示而不是隐藏
- 主表是**通常状态**；其它状态的差异另列在「状态变化」块里
- 源数据没有名字的部位显示为 `隐藏部位N`

**名字模糊匹配**（免依赖，不引第三方库）：

| 输入 | 行为 |
|---|---|
| `火龙天鳞` | 归一化去「的」→ 命中 `火龙的天鳞`，并提示「已自动匹配」 |
| `爵銀龍`（繁体） | 繁→简映射后命中 `爵银龙` |
| `爆锤龙` | 编辑距离 1 且候选唯一 → 自动匹配 `爆鳞龙`，并提示 |
| `骚鸟` | 同时接近 搔鸟 / 伞鸟 / 丸鸟 → **不替你猜**，把候选列出来让你选 |

匹配范围：素材名、怪物名、武器名、技能名。距离 2 只在候选唯一**且**错字
占比 ≤ 1/3 时才采用（否则「攻击珠」会莫名匹配到「电击袋」）。

怪物卡的方块按「该素材的最高获取概率」降序，稀有素材（稀有度 ≥ 7）的方块转金色；
每块最多列 5 条获取方式，素材超过 10 种时余下的归入「其它素材」方块列出名字
（不会静默丢弃）。

## 安装

1. 把整个 `astrbot_plugin_mh_material` 目录放进 AstrBot 的插件目录：
   `<AstrBot>/data/plugins/astrbot_plugin_mh_material`
2. 装入依赖（AstrBot 主环境通常已带 Pillow ≥ 10）：
   ```
   pip install -r requirements.txt
   ```
3. 在 AstrBot 面板重载插件。

## 数据

插件不联网，只读一份本地快照，因此查询是纯内存操作、响应快且不受外部服务影响。

### 快照位置

按以下顺序查找，先命中先赢：

1. 环境变量 `MH_MATERIAL_SNAPSHOT` 指定的路径
2. `<AstrBot>/data/plugin_data/mh_material/snapshot.json` — **正式部署位置**
3. 插件自带的 `data/plugin_data/mh_material/snapshot.json`

### 重新生成快照

**用 `tools/rebuild_snapshot.py`，不要单独跑 `extract.py`。**

| 步骤 | 脚本 | 写入 | 是否需要联网 |
|---|---|---|---|
| 1 | `extract.py` | 基础表（**会重写整个快照**），含野外采集点、傀异调查报酬、部位/剥取细分 | 否 |
| 2 | `fetch_habitats.py` | `monsters[].map_names`（栖息地图，gamecat） | 是（缓存优先） |

```
python tools/rebuild_snapshot.py
python tools/rebuild_snapshot.py --out "<AstrBot>/data/plugin_data/mh_material/snapshot.json"
python tools/rebuild_snapshot.py --skip-fetch    # 只跑第 1 步，完全离线
```

脚本跑完会**校验各数据块是否都在**（武器 ≥3500、装饰珠 ≥250、野外采集点 ≥75、
栖息地图 ≥90、部位/剥取细分 ≥900、傀异调查报酬 ≥50、怪物弱点 ≥70、
部位名日文泄漏 = 0），不足会明确报出来。

> ⚠️ **注意**：`extract.py` 会**重写整个快照**。所以重建必须用
> `rebuild_snapshot.py`（它按正确顺序串起各步并在最后校验），
> 不要单独跑 `extract.py` 去覆盖已有的快照文件。

单独跑 `extract.py` 时的可选参数：

```
--mhrice <路径>     指定 mhrice.json
--items <路径>      指定 items.json
--pretty            缩进输出，便于人工检查
```

### 源数据

`tools/extract.py` 从这两个文件提取：

- `mhrice.json`（约 118 MB）— 游戏文件转储，提供掉落表、任务表、地图与中文名
- `items.json` — 物品库，提供素材中文名（简中）

采集点数据现在**也从 `mhrice.json` 提取**（见下），不再需要联网抓取。
`armor.json` / `equip_skills.json` / `normal_decos.json` 目前**不使用**（属于配装数据），
详见下面的「扩展」。

### 野外采集点（来自游戏本体数据）

野外采集点（矿脉、骨冢、蜂巢、蘑菇…）的「**节点类型 + 地图 + 难度 + 数量 + 概率**」
全部来自 `mhrice.json` 的两张表，由 `extract.py` 直接产出：

| 表 | 提供 |
|---|---|
| `item_pop_lot.param` | 每个 **(pop_id, field_type)** 的采集掉落（下位/上位/大师各 10 槽） |
| `maps[地图号].pops[].kind.Item.behavior` | `pop_id` 出现在哪些地图、`pop_category` 节点类别 |

关键理解：**`field_type` 就是地图号**（`-1` 表示该类型的通用掉落，
被同 `pop_id` 的「地图专用」条目覆盖）。`pop_category` 决定节点名，
例如 5 = 矿脉、6 = 骨冢、3 = 捕虫点、7 = 蜂巢。

于是卡片能写清「**水没林 · 骨冢 · 大师 20%→x1，10%→x2**」，
而不只是「水没林」。同一张图上同种节点的**多个采集点**用 ①② 区分——
这正是早期 Kiranico 表里「同一地图同一难度出现两块不同概率」的真实原因。

实测 `item_pop_lot` 覆盖 180 个物品（快照按素材类收 82 个），
是 Kiranico 那 47 项的**超集**，且数值完全一致（重泥骨：水没林·大师 20%/10%）。

> 早先这一步靠 `tools/fetch_gathering.py` 抓 Kiranico，现已由游戏数据取代：
> 既有节点类型，又是逐地图的，还免去联网与许可证问题。
> 该脚本仍保留在仓库里作为参考与后备，但**不在重建管线中**。

节点类别名是按该类别下实际出现的物品**逐个核对**后起的描述性名称——
源数据没有官方节点名（`map_icon_list` 的 GUID 解析出来是物品名与说明，不是节点名）。

### 怪物栖息地图（来自 gamecat.fun）

「这只怪/小动物去哪张图找」来自 [gamecat.fun（游猫网）](https://gamecat.fun/rise/zh/)。
由 `rebuild_snapshot.py` 的第 3 步调用：

```
python tools/rebuild_snapshot.py                # 推荐：三步一起跑
python tools/fetch_habitats.py --probe          # 只验证解析
```

用 MediaWiki API 批量取怪物页「怪物简介」段的 `出现场地：` 字段（112 只怪物分 3 批，
每批 ≤50 个标题），只提取「怪物 → 地图名」映射，缓存到 `habitat_cache.json`。
实测 105 只怪物有地图字段，写入快照 102 只。

**为什么需要单独抓**：`mhrice.json` 里**小动物的地图数据是空的**
（`small_monsters[].habitat_area` 恒为 `null`，
`ecological.stage_info_list` 实测 37 只里只有 2 条有值），所以无法从源数据得到。

**同样未声明许可证**，处理方式与采集点一致：只取事实字段、标注来源。

## 数据可信度说明（重要）

这份快照有三处已知的局限，都是**源数据本身**的限制，不是插件 bug。使用前请知悉：

### 1. 地图 12 / 13 的名称是推断值

源数据的 `map_name` 表只有官方编号 1~11 的名字，但大师任务里用到了 `12` 和 `13`。
插件按「任务出场怪物」推断为 **12 = 密林、13 = 城塞高地**。

**已获独立印证**：Kiranico 的采集点数据里直接出现「密林」「城塞高地」两张地图
（例如「有苔藓的重土骨」只在密林、「受损的重古骨」只在城塞高地），与推断一致。
不过源数据里仍没有 `12 → 密林` 的直接对照，快照里保留 `"origin": "inferred"` 标注，
卡片底部也会显示「地图 … 为推断值」。

### 2. 怪物名映射

官方名称表的连接键是 `enemy_type`：条目名 `EnemyIndex{et:03d}`，
大师位在 `monster_names_mr` 里加 `_MR` 后缀。实测覆盖：

| 对象 | 命中 |
|---|---|
| 大型怪 | 78/79 |
| 小动物 | 37/37 |

大型怪与小动物的 `enemy_type` 值域**完全不重叠**（大怪 0..46 / 76..98 / 107..115，
小怪 47..75 / 99..106），所以一张表共用，不存在歧义。

3 只大师位小动物（`et=48/71/74`）落在名称表的缺号上，用 `et-1` 取到其基础形态名。

**已知不确定项**：`em=131` 在名称表里没有条目、也没有掉落记录，因此不出现在卡片里
（快照只收录有掉落记录的怪物）。

### 2b. 小动物名映射

小动物（精灵鹿、丸鸟、野猪…）用独立的 `Ems` id 空间，名字同样走官方键
`EnemyIndex{enemy_type}`，实测 **37/37 有名字**。

其中掉落物里不含自己名字的几只（艾露猫、梅拉露、砂鱼、变形幼冰鲨）无法用掉落物
自证，已逐只人工核对。**艾露猫与梅拉露的掉落完全相同**（肉球印章、肉球优待券），
只能按名称表区分，属推断。

### 2c. 别名（日文名）已停用

`monster_aliases` 表的编号与名称表对不上（按编号取会取到下一只怪的别名），
且存在「霸主・火龙」被当成「火龙」这类错例。别名在卡片上只是装饰，
**错的名字比没有更糟**，所以直接不输出。

### 2d. 掉落物里的非素材类物品

小动物会掉结算道具和消耗品（丸鸟蛋 `CarryPayOff`、生肉、药草、怪物体液）。
早先快照只收录 `Material` / `OffcutsMaterial` 类型，这些物品被过滤掉后，
掉落记录指向一个**不存在的 id**，卡片上就出现空白的素材名
（「掉落物 1个 100%」后面没字）。

现在**所有被掉落记录引用到的物品都会进表**（快照 1349 → 1384 项）。
校验：6475 条掉落记录里解析不到物品名的为 **0 条**。

### 2e. 傀异调查（怪异调查）报酬：另一张独立的表

怪异化素材（「怪异化的凶刚角」等，稀有度 9，共 54 种）**在 `monster_lot` 里完全没有**。
早先只读 `monster_lot` / `monster_lot_mr`，于是这些素材查询时一律显示
「暂无掉落记录」——而玩家其实能在傀异调查里从怪异化怪物剥取或部位破坏拿到。

来源是另一张独立的表 `mystery_reward_item`，每条形如：

```json
{"em_type": {"Em": 7}, "lv_lower_limit": 161, "lv_upper_limit": 199,
 "hagibui_probability": 40, "reward_item": {"Normal": 2911},
 "item_num": 1, "is_special_mystery": false}
```

即「某只怪异化怪物，在某个傀异等级区间内，以某概率掉落某素材」。
`build_anomaly_rewards()` 会：

1. 按 `(item, 怪物)` 聚合等级区间；
2. **合并相邻且概率/数量相同**的段——但**概率不同的段绝不合并**。
   雷狼龙 161–199 是 35%、201+ 是 40%，若为省行数而合并取最大值，
   就会把 35% 误报成 40%；
3. `is_special_mystery` 不参与合并比较：它只标记「特殊傀异」玩法差异，
   不影响概率，参与比较会产生「Lv161–300 40%，Lv300 40%」这种冗余行。

卡片上因此显示为：

```
■ 傀异调查
    角龙　Lv161–300 40%
    雷狼龙　Lv161–200 35%，Lv201–300 40%
    (傀异调查（怪异调查）中剥取或部位破坏获得)
```

同时「来源怪物 N 只」的计数也把傀异调查里的怪物算了进去，
不然会出现「来源怪物 0 只」却列着三只怪的矛盾。

### 3. 部位破坏 / 剥取：已细分到具体部位

**关键结构**：每一种掉落方式的 `{kind}_item_id_list` 都是「**类型数 × 10 槽**」，
类型身份在同行另一个字段里：

| 方式 | 类型字段 | 取值 |
|---|---|---|
| `parts_break_reward` | `parts_break_list` | `RandomId`（部位身份） |
| `hagitory_reward`（剥取） | `enemy_reward_type_list` | `MainBody` / `PartsLoss1` / `PartsLoss2` / `Unique1` |
| `drop_reward`（掉落物） | `drop_reward_type_list` | `DropItem` / `DropItem2` … |
| 目标报酬 / 捕获 / 随从 | 无类型字段 | 即 1 个类型 |

实测六种方式在**全部 248 行**上都满足「长度 == 类型数 × 10」，无一例外。
注意类型列里的 `"None"` 是**占位符**，必须保留（它占一个组位），
组数取类型列全长、槽宽恒为 10。

部位名用**游戏官方的简体中文词**：`parts_type` 表的键是怪物的 `em_type.Em`，
取其中的 `text_for_monster_list`（该字段引用的文本能在 `hunter_note_msg` /
`hunter_note_msg_mr` 里解析到，`text` 字段的引用在这份数据里没有定义）。
同一个 `(Em, RandomId)` 有多个候选时取 `enemy_type_list` 最短的那个（最专属）。

`collider_mapping.part_map`（逐怪日文）只作兜底：它的键是 `parts_group`，
与 `parts_break_list` 的 `RandomId` 不是同一个编号空间，需要经怪物的
`parts_break_reward` 桥接才能用。翻不出中文的**返回空而不是显示日文**。

剥取也细分了：`MainBody` = 本体剥取、`PartsLoss1` = **尾巴剥取**
（实测首个物品名 79/95 含「尾」，其余是「雌火龙的棘」这类同样来自尾巴的素材）、
`PartsLoss2` = 切断部位、`Unique1` = 特殊（岩龙的矿脉剥取、雷狼龙的超电状态）。

实测：1027 条部位破坏记录**全部标出具体部位**，且**零日文/内部词泄漏**。
剥取侧的细分同样是 100%（本体 776 / 尾巴 326 / 特殊 21 / 切断部位 8）。

## 与最初需求的两点差异

开发时按实测数据做了调整，这里明确记录，避免误解：

1. **任务信息分两块呈现，来源不同。**
   - **可刷任务**：通过「哪些任务会出场掉落该素材的怪物」推导，标注了具体打哪只怪。
     这是怪物素材（如龙玉、天鳞）获得任务信息的主要途径。
   - **任务报酬**：任务的结算奖励表（`quest_data_for_reward`）里直接产出的素材，
     例如「妖辉石」完全没有怪物掉落来源，只在任务 315100 / 315108 的结算奖励里。
     只覆盖一部分素材（本快照 978 种素材中有 181 种是**仅任务报酬**来源），有才显示。
2. **活动任务与常驻任务混排**，活动任务带【活动】前缀标注（活动任务是限时轮换的）。

## 疑难排查

**查询没反应 / 回了「用法：/mh ...」**
说明参数没传进 handler。本插件**不依赖** `@filter.command` 的注解式参数解析
（AstrBot 的 `CommandFilter.init_handler_md` 直接读 `inspect.signature` 的注解，
而 `from __future__ import annotations` 会把注解变成字符串，导致解析失效），
改为在 handler 里解析消息文本。如果你改动 `main.py`，请保持这个方式。

**「没有找到名为 XXX 的素材」**
先确认名字写法（用 `/mh 素材 <名字的一部分>` 试模糊匹配，会列出候选）。
若确实不在其中，说明该素材不在本快照覆盖范围内。

**素材查到了但显示「暂无掉落记录」**
这是数据事实，不是缺失：本插件的快照包含全部 1349 个素材/余料类物品，
其中约 570 个**没有**怪物掉落或任务报酬记录——它们来自野外采集、交易，
或源数据（`mhrice.json`）本身没有收录掉落表。当前版本不查询采集点。

## 导入约定（修改代码时注意）

AstrBot 是把插件目录当作**包**加载的，因此插件内部的模块必须用**相对导入**：

```python
# 正确
from .render import Card
from . import commands as cmd

# 错误 —— 会报 No module named 'render'
from render import Card
```

`tools/` 下的脚本不受此约束（它们不被 AstrBot 加载），
但 `tools/selftest.py` 仍按包导入插件，以保证测的就是实际部署的导入方式。

## 卡片外观（怪物猎人风格）

卡片刻意做成怪猎 UI 的观感，排版称为「公会台账」。要素与用意：

| 要素 | 做法 |
|---|---|
| 切角标签 | 块标题是一条 45° 切角的金色标签（稀有素材的方块转亮金） |
| 台账行 | 块体是连续的行（发丝分隔线 + 隔行淡底 + 左侧图标轨道），不是一行一个框 |
| 公会徽记 | 矢量绘制的翼 + 盾 + 中央菱形，配字距拉开的 `MONSTER HUNTER RISE` 报头 |
| 指标条 | 卡名下方一行「标签 + 值」，用竖线分隔（取代中缀点拼接的副标题） |
| 稀有度刻度 | 菱形点数，按怪猎稀有度配色（1-2 灰 / 3-4 绿 / 5-6 蓝 / 7 紫 / 8 红 / 9-10 金） |
| 部位图示 | 爪痕（怪物）、定位菱形（地图/采集点）、旗标（任务）、傀异核（傀异调查） |
| 概率量条 | 数值列右对齐，其左侧一条**按本块最大值相对缩放**的暗绿刻度轨 |
| 锋利度条 | 赤 橙 黄 緑 青 白 紫 七色（武器详情卡） |

三个实现细节值得记下来：

* **3 倍超采样**：PIL 画多边形/细线不做抗锯齿，直接画会让切角与括号出现锯齿。
  内部统一用 3 倍分辨率绘制、最后 LANCZOS 缩回，代码里所有尺寸都用「逻辑像素」书写。
* **高度按真实光标裁剪**：先在超高画布上正常绘制，最后按实际用到的光标位置裁。
  用「预估高度」建画布会让预估与绘制两套算术漂移，卡片底部会被裁掉。
* **标签框与行带按字形 bbox 推导**：PIL 的 `draw.text(xy)` 把 xy 当**绘制原点**
  而非字形上沿（msyh 的字形上沿在原点之下约 0.25em、下沿约 1.22em），
  手写框高会出现「文字露在框外」。统一用 `text_in_box()` 从字体实际字形算尺寸。

## 渲染后端

默认用 PIL 本地绘制，**不依赖 AstrBot 的文转图服务**（该服务默认关闭）。
出图路径是 `LedgerRenderer`（「公会台账」排版）。

`CardRenderer`（1.2.x 的旧排版）仅保留给 HTML 后端复用同一套 `Card` 数据模型，
**不再是出图路径** —— 两套设计并存只会让卡片风格不一致。

如果你在 AstrBot 面板里配好了 t2i，可以切到 HTML 后端走官方服务：

```
set MH_MATERIAL_RENDER=html
```

注意：HTML 后端仍是 1.2.x 的旧视觉，与图片后端不一致，**仅作应急**。

渲染失败时会自动回退成纯文本，用户始终能看到内容。
